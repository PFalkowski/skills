- Use `workhorsePath`, not `{name:}`. Pass an absolute `scriptPath` to `workflows/sdlc-workhorse.js` in the skills repo or the installed plugin. Leave it out and `high` tickets return blocked instead of silently degrading to a lesser process, because an un-run gate is visible and a skipped one is not.
- On Windows, CRLF line endings in a workflow file break `scriptPath` dispatch. If the approval dialog rejects a `scriptPath` dispatch as containing hidden control characters, the target `.js` has CRLF line endings and the validator is counting each `\r`. A `.gitattributes` rule (`*.js text eol=lf`) is the right repo-level fix. It only takes effect on a fresh checkout, though, and `core.autocrlf=true` can still reintroduce CRLF, so it is no reliable guarantee on an existing clone. The dependable workaround, which does not depend on the environment, is to read the script file and pass its contents inline via `script` (still this repo's copy, just LF-clean) instead of `scriptPath`. Do not re-diagnose it as file corruption or a permissions problem.
