## Talking back to a running agent

- A live subagent (spawned with `Agent`, still resident) gets `SendMessage` with the verdict block. Keep it alive only while the next leg needs its context. Otherwise let it end and brief a fresh one with the verdict handed in.
- A fresh process (`sdlc-old-fashioned` Dial 2, a `claude` OS process) gets the answer written into the backlog file the next phase reads, and the phase brief points at it.
- A workflow has no channel into a running script. The verdict shapes the arguments of the *next* dispatch.
- An agent in another session (the pasted-report case) gets the verdict posted where it will look, as a comment on its PR or ticket. The report to the human names the agent to forward it to.
- On the board, every DEFER files (or drafts, under `tickets=draft`), every state change transitions, and every verdict on a PR or ticket is a comment there. Ticket text meets the [readiness bar](../triage/READINESS.md). The manager never closes a ticket it has not verified is done, and never deletes one.
