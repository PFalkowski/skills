## Step 0: resolve the PR and check out its branch

1. Identify the PR from the argument, which may be a number, a URL or the current branch.
   - On GitHub, run `gh pr view <n> --json number,url,title,headRefName,baseRefName`.
   - In a cloud session, `gh pr` commands fail on GraphQL here and at every later step. Instead, read the PR (state, head, base) with `gh api repos/{owner}/{repo}/pulls/<n>`, the review bodies with `gh api --paginate .../pulls/<n>/reviews`, and the threads with `gh api --paginate .../pulls/<n>/ccr/review_threads`. Check out with `git fetch origin <head> && git checkout <head>`. Work only on a PR whose head branch the session may push ([cloud sessions](../docs/cloud-session.md)).
   - On Azure DevOps, delegate resolution and all later thread mechanics to [AZURE-DEVOPS.md](../code-review-grill/AZURE-DEVOPS.md).
2. Check out the PR head branch with `gh pr checkout <n>`, or fetch and checkout. If the current checkout holds unrelated dirty work, use a worktree rather than disturb it.
3. Pull the review threads. By default, take unresolved/active ones only.
   - On GitHub, `gh api --paginate repos/{owner}/{repo}/pulls/<n>/comments` returns inline comments and `gh pr view --json reviews,comments` returns review bodies. Group them into threads and drop the resolved ones. The reliable source for resolution state is GraphQL `reviewThreads.isResolved`, read with `gh api graphql --paginate` and an `$endCursor` variable.
   - On Azure DevOps, use the threads API via the sibling skill and keep `status=active`.
4. Present the inventory as a numbered list (`C1`, `C2`, …) giving file:line, author and a one-line gist. This numbering is used everywhere below.
