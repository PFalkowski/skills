- `workhorsePath`, not `{name:}`. Pass an absolute `scriptPath` to `workflows/sdlc-workhorse.js` in the skills repo or the installed plugin. Without it, `high` tickets return blocked rather than silently degrading to a lesser process. An un-run gate is visible, and a skipped one is not.
- CRLF workflow files break `scriptPath` dispatch on Windows. If the approval dialog rejects a `scriptPath` dispatch as containing hidden control characters, the target `.js` has CRLF line endings and the validator is counting each `\r`. A `.gitattributes` rule (`*.js text eol=lf`) is the right repo-level fix, but it only takes effect on a fresh checkout, and `core.autocrlf=true` can still reintroduce CRLF, so it is not a reliable guarantee on an existing clone. The dependable, environment-independent workaround is to read the script file and pass its contents inline via `script` (still this repo's copy, just LF-clean) rather than `scriptPath`. Do not re-diagnose it as file corruption or a permissions problem.
