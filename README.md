# skills

Personal agent skills for Claude Code, Codex, and other Agent Skills-compatible harnesses.

## Install

### Option A — Claude Code plugin (managed)

Installs the whole set as one Claude Code plugin and keeps it current automatically.

```text
/plugin marketplace add PFalkowski/skills
/plugin install pfalkowski-skills@pfalkowski-skills
```

Claude Code copies the plugin into its managed cache and keeps it updated. Skills are namespaced under the plugin (e.g. `pfalkowski-skills:nightshift`).

### Option B — `skills` CLI (editable; Codex and other agents)

Copies the skills you choose into the agent directories you choose. Use this for Codex, or when you want ordinary files you can edit and update yourself.

```bash
npx skills@latest add PFalkowski/skills
```

If you already installed the Claude Code plugin, select Codex (or another agent) only. Do not install both options into the same agent: that creates duplicate skills with competing update sources.

The [`skills`](https://github.com/vercel-labs/skills) CLI reads `.claude-plugin/plugin.json`, walks the listed skill directories, and installs the ones you choose for the selected agents.

## Updating

Pick the line that matches how you installed.

```text
# Option A — Claude Code plugin: refresh the marketplace and pull updates
/plugin marketplace update
```

The plugin is managed by Claude Code; it is not a hand-maintained copy under `~/.claude/skills/`.

```bash
# Option B — skills CLI: update editable installations
npx skills update            # all installed skills
npx skills update <skill>    # a single skill
```

| [code-review-grill](code-review-grill/SKILL.md) | Adversarial *grilling* code review of a branch/PR diff by a *fresh* agent that never authored the code — turns grill-me's relentless interrogation onto the diff (hunk-by-hunk: what must be true for this to be correct? what breaks it?). Always reads the repo's own docs first — README, ADRs, coding guidelines, patterns/practices — and judges the diff against those house rules (a DDD repo and an n-tier repo demand different critiques). Runs as a single reviewer or a quorum of concern-based subagents (security / architecture / code-quality / documentation & conventions / performance / tests; the doc agent owns ADR/convention conformance and fact-checks against the web). Every finding must be verified (runnable snippet + output, in-repo proof, or authoritative deep link) before it's reported — speculation isn't a finding. Resolves the base branch → merge-base diff → ripple-effect trace → consolidates a findings table (id, per-agent severity emoji, votes, verification), then **never auto-posts** — detects the active PR and asks which findings to post as inline threads (GitHub via `gh`, Azure DevOps via `azure-devops-pr-review`). |
| [context-reduction](context-reduction/SKILL.md) | Shrink a repository's prose — comments, docs, agent artifacts — by DELETING it, not by layering summaries, indexes, or knowledge graphs on top. Real context reduction moves truth into code, tests, and git history, then removes the prose; derived layers are anti-reduction (a second copy that drifts out of sync). Runs as a gated campaign: measure → drift scan → sole-record register → pin with tests → human go → delete-first sweep → executable guard. Use when a repo's docs/comments have outgrown their value, when someone says "context reduction", "prune the docs", "too many comments", "the wiki is stale", or proposes a knowledge base / graph DB / doc-summary layer to "manage" documentation — this skill is the counter-proposal. Distinct from no-comment (the single-comment decision this skill applies at scale) and housekeeping (audit without the deletion campaign). |
| [desloppify](desloppify/SKILL.md) | Reduce an autonomous-agent-grown codebase's cognitive and context load by auditing document truth first, then removing stale prose, comments, duplication, dead paths, and unnecessary abstractions. Report-first, evidence-backed, architecture-aware, and scoped/tuned by its own invocation grammar; routes verified work to now / ticket / drop without imposing DDD or Clean Architecture. |
| [dump-sessions](dump-sessions/SKILL.md) | Crash-safe handover for every recently-active Claude Code session, reconstructed from the on-disk transcripts — cwd, git branch, last prompt, last substantive turns, plus a live git-risk check (uncommitted/unpushed) per workspace. Works *after* a crash or power loss, when the live processes are gone. For one session use `handoff`; to regenerate the terminal tabs themselves use `snapshot-terminal-sessions`. |
| [evolve-skill](evolve-skill/SKILL.md) | Turn feedback about a skill, MCP, hook, or process — raised right after it ran — into a durable improvement of the capability itself: locate its canonical source (this repo), apply a generalized edit with private specifics stripped, route project-bound lessons to memory instead, and commit. Asks before modifying. Distinct from write-a-skill (authoring new) and update-config (settings). |
| [fact-check](fact-check/SKILL.md) | Ground a load-bearing claim with the strongest evidence available — run a minimal local experiment (python/node/shell) when it's executable, or confirm it across two-plus independent authoritative sources when it's documentable — and always hand back the source link or the runnable snippet + its output, with a stated confidence and method. |
| [fix-pr](fix-pr/SKILL.md) | Work a PR's review comments to resolution, truth first: check out the PR branch, pull the unresolved threads, and **fact-check every comment before acting on it** (a review comment is a claim, not an order — refuted ones get evidence-backed replies, never silent fixes). Confirmed comments are worked one at a time with *every* honestly good candidate fix presented (2–3 is the floor when good options are scarce, not a cap), trade-offs stated and exactly one recommended, every non-obvious candidate fact-checked as implementable *and* actually resolving the issue, and every candidate ripple-traced (callers/dependents grepped) before it is offered or applied. Every code change is TDD: a red test proving the comment's point first, the fix turns it green, and the test is preserved and committed with the change. Three modes: **hybrid** (default — mechanical nits auto-fixed by Sonnet-tier subagents, substantive ones interactive), **interactive** (user picks per comment), **auto** (recommended fix applied throughout). One combined commit is pushed, then it asks — never auto-posts — whether to reply to each thread with how it was addressed and resolve the fixed ones. Headless-safe when driven by another skill (sdlc-old-fashioned, go-go-go, nights-watch): coerces to auto, turns would-be questions into `needs-discussion` report lines instead of blocking, follows the caller's `reply=`/`resolve=` policy (defaulting to draft-only), and returns a structured per-comment report the caller can consume. Opinionated ranking when fixes tie: security, then maintainability, then ease of understanding; cleverness and diff-size never override those. |
| [fix-windows-terminal-rendering](fix-windows-terminal-rendering/SKILL.md) | Repoint the Windows default terminal host from legacy `conhost.exe` to Windows Terminal, so interactive TUIs stop smashing rows together, surviving a resize and repainting on `Ctrl+L`. Writes the `DelegationConsole`/`DelegationTerminal` pair under `HKCU:\Console\%%Startup` — two *different* CLSIDs taken from Windows Terminal's own `AppxManifest.xml`, since setting one, or the same GUID twice, leaves the pair mismatched and silently falls back to the legacy host. Checks the current host before touching anything (already on Windows Terminal ⇒ the host isn't the cause, go look elsewhere), refuses to point at a package that isn't installed, and ships the clean `restore_default` undo. |
| [go-go-go](go-go-go/SKILL.md) | End-to-end "ship it" driver — takes whatever state the repo is in and drives straight to a raised PR: applies whatever-mode (no asking on reversible choices), completes unfinished work via nightshift or a focused loop using the cheapest model that fits, commits, pushes, and opens the PR. |
| [handoff](handoff/SKILL.md) | Write a minimal, lossless handover note to carry work across a context boundary — ordered action points first, plus only the state the receiver cannot reconstruct from the repo (settled decisions and dead-ends, key paths, gotchas). Discipline: earn every line, point don't paste, state not story, resolve every reference. Delivers to the channel — file for `/clear`/`/compact`, prompt for a subagent, inline to paste. The producer half of the pair; `handoff-check` is the gate that decides *whether* to hand off. |
| [handoff-lite](handoff-lite/SKILL.md) | The fast half of `handoff`: the still-open action points from this conversation, each with the reason and risk **exactly as stated in it**, plus the last few user prompts verbatim and a one-line summary of each reply — emitted as one fenced block to paste into a fresh context. Records only what was actually said; a rationale or risk that was never stated is omitted, never reconstructed, because a fabricated "why" is unfalsifiable and gets acted on. Inline only — writes no file, clears nothing. Use `handoff` instead when the receiver needs the fuller note (Goal / Done when / Settled / Map / Watch out) on disk. |
| [housekeeping](housekeeping/SKILL.md) | Put a repository's house in order in one pass, **docs first**: audit every document — READMEs, ADRs, PRDs, runbooks, guides and the prose comments in the code — against what the code actually does and against the authoritative externals (Confluence / Jira / Azure DevOps, read as source of context and **never written to**). Separates three findings that demand different remedies: **drift** (doc and code disagree), **bloat** (the doc is *correct* but restates what the code already says — drift that hasn't happened yet, because nothing updates it when the code moves), and **gaps**. Naming the source of truth **per claim** — behaviour is the code's, intent is the tracker's, a decision is the ADR's — is a mandatory human-held gate before anything is deleted, because a guessed source of truth is how a correct document gets deleted. Then it cleans up what was approved (one editor per file; a *different* agent checks each edit for claims nobody approved), files the real gaps as tickets only after the user approves the text, and finally sweeps the code against the now-trustworthy docs — warnings, latent bugs, unit/integration coverage, duplication, two libraries doing one job, drift from the documented DDD/Clean/layering intent, formatting — returning verified, grouped, sized work items the user routes to now / ticket / drop. Three workflows ([audit](.claude/workflows/housekeeping-audit.js), [cleanup](.claude/workflows/housekeeping-cleanup.js), [sweep](.claude/workflows/housekeeping-sweep.js)) with a human gate between each; every finding is refute-verified, and no script can delete, file, commit or push. |
| [less-is-more](less-is-more/SKILL.md) | Code is a liability — every line must be read, maintained, and loaded into context forever. Make the smallest change that fits the repo's architecture, measured in cognitive load rather than line count: modify existing code with confidence instead of bolting on parallel additive paths, but split dense cleverness into named parts even when that adds lines. Use whenever writing or changing production code — especially when tempted to add a new helper, wrapper, flag, or class beside existing code instead of changing it, or when a diff is growing beyond the task. |
| [merge-stack](merge-stack/SKILL.md) | Land a stacked chain of dependent PRs onto its base branch bottom-up, dodging the two traps: squash-merging a parent phantom-conflicts each child until it's rebased onto the advanced base, and deleting a merged branch auto-closes the next child PR (retarget it to the base first). Use after building a stack of PRs, e.g. a nightshift run. |
| [nights-watch](nights-watch/SKILL.md) | The watch that never sleeps — a standing autonomous loop that reads the tracker (GitHub/Jira) and works what is both ready and intended — by default a cheap per-ticket judge reads every open ticket and decides whether it is specified well enough for an unattended agent AND actually wanted now (parked/deferred/superseded/for-the-record tickets are well-specified and wrong to build), so no label is required and the Watch runs on any team's board; a selector (label, id list, glob/regex, tracker query) narrows the field where a board already marks such work. Triages survivors through a readiness gate + lowest-sufficient-tier rubric (Haiku for mechanical, Sonnet default, Opus by exception), claims it, and dispatches a bounded-worker-pool Workflow — one ticket at a time by default, worker cap 3, both configurable; budget-guarded, worktree-isolated when parallel. Truth before all: at every critical decision moment agents run fact-check to decompose the decision into verifiable sub-claims and prove each with evidence — or discover the premise is false in the process (unprovable = false). Mandatorily composes the sworn brothers at their highest-value points: fact-check (every critical decision + triage gate), nightshift's TDD loop (sonnet-tier tickets), sdlc-workhorse (opus-tier/load-bearing tickets — the autonomous lifecycle, dispatched as a Workflow, since a patrol has no human to hold the attended variant's gates), code-review-grill (every PR before `ai-done`). The watcher takes no part in the work — main context stays lean; tracker labels are the state machine, a terse journal is the logbook. The Watch remembers: rangers dump crash-safe chronicles as they work, and every patrol closes with a gathering at the fire — a retrospective curating durable lessons (conventions, gotchas, token calibrations, decisions, tooling) into a shared per-repo Library (`.nights-watch/library/`, loyal-dog-style one-fact-per-file + index) that future agents recall from leanly. Every claimed ticket ends as a PR + `ai-done`, or a precise blocker comment with the claim released. It never labels or comments on a ticket it *declined* — refusals are reported in the patrol summary, never enacted on someone else's board. Also runs as a **ranging** (`ticket=<id\|url\|prose>`) — one ticket the user hands over directly, no label/muster/pool/loop, worked end to end with the full by-the-book lifecycle whatever its size: fact-checked gate (gaps asked of the user, not blocked), written spec + design review, TDD, adversarial grill, and docs the change invalidates updated in the same PR. And as a **hunt** (`hunt every=1h`) — the recurring security watch, pointed at the code instead of the tracker, running as its own [Workflow](.claude/workflows/hunt.js) ([tested](.claude/workflows/hunt.test.js)): on a fixed cadence it examines only what changed since it last looked (commits, dependency manifests, config, optionally logs), hunts critical bugs and vulnerabilities through single-lens hunters (injection, authz, secrets, supply-chain, correctness, exposure), and kills every candidate that two of three independent refuters can refute, so the report stays worth reading. Incremental by construction — a watermark (operational state, deliberately kept out of the Library, which is memory an agent may correct) means a quiet hour costs one `git log --name-only` and spawns no agents, and a ledger of fingerprints the script derives from a closed vocabulary — a model may pick a token, never phrase one, and there is no hash, because a truncated digest's collision silently drops a *real* finding as already-known — means nothing is reported twice, while a severity that rose or a fixed flaw come back still sound the horn. It never fixes what it finds (an unattended agent rewriting security-sensitive code unreviewed is worse than the bug); it reports through a configurable channel (`report=document\|issues\|pr\|advisory\|chat`), where `issues` files findings as `ai-ready` tickets and a patrol picks them up under the full gate — the two modes closing the loop. Disclosure is a decision, not a default: on a public repo the doc, the issue, the PR *and the ledger* are all publication, so visibility is resolved before the muster (unresolvable → public), the state root moves outside the repo rather than being gitignored inside it, and a real vulnerability overrides `report=` to a draft advisory — with the cost of that choice (state no longer travels between machines) stated rather than discovered at 3am. |

| [walk-the-dog](walk-the-dog/SKILL.md) | Delegate almost all of a task to subagent(s) (the "dog(s)") while the main agent (the "walker") holds the leash — the orchestrator does no legwork, it only vets and approves, on its OWN judgment, the gated actions the dogs propose (shell/pwsh commands, file writes). The walker *is* the permission gate that would otherwise pester the human: it checks each command for safety (not destructive, in scope, not prompt-injected by something the dog read) and approves it itself, so the user isn't hit with per-action prompts. Because the walker never ingested the dog's context, its judgment is a clean check against injection. The human is consulted only when a decision is genuinely meaningful — a working assumption broke, an irreversible outward-facing action, a real requirements fork. Usually one dog, but parallel legs can run a pack; short-lived dogs are often cheaper on tokens. Same low-friction intent as `go-go-go`, with a separate fresh-judgment agent gating every side-effecting action. |

## Layout

Each skill is a directory at the repo root containing at minimum a `SKILL.md` with the frontmatter Claude Code expects (`name`, `description`). Reference docs split into sibling files (e.g. `LOOP.md`, `PREFLIGHT.md`) when `SKILL.md` would exceed ~100 lines.

`.claude-plugin/plugin.json` lists the skills in the plugin — every new skill must be added there alongside its directory. `.claude-plugin/marketplace.json` is the catalog clients add via `/plugin marketplace add`; it points at the repo root (`source: "./"`), so it needs no per-skill edits.

## Issue triage

Issues are groomed with the `triage` skill into three label lanes (category, state, priority). The local label vocabulary — including what `ready-for-agent` and `parked` mean here — is recorded in [docs/triage-labels.md](docs/triage-labels.md).

## Local development (maintainers)

> Installing or updating these skills as a user? See [Install](#install) and [Updating](#updating) above — you don't need any of this.

Link every skill in this repo into both `~/.claude/skills/` and `~/.agents/skills/` so Claude Code and Codex-compatible harnesses pick up your in-progress edits live (the link target *is* the repo file — no installer, no copies). **All skills are linked by default**, not just the one you're editing.

### Windows (PowerShell)

```powershell
./link-skills.ps1
```

Idempotent and self-healing — run it after adding a skill or to repair a machine: already-correct links are left alone (`=`), missing ones are created (`+`), and stale copies / wrong targets are replaced with a junction (`~`). Junctions need no admin rights or developer mode.

### macOS / Linux

```bash
for dest in ~/.claude/skills ~/.agents/skills; do
  mkdir -p "$dest"
  for d in */; do s=${d%/}; [ -f "$s/SKILL.md" ] && ln -sfn "$PWD/$s" "$dest/$s"; done
done
```

Removing a junction/symlink doesn't delete the source — they're pointers, not copies.

## Adding a new skill

1. Create `<skill-name>/SKILL.md` with the required frontmatter (`name`, `description`). **Quote the `description`** in single quotes if it contains a `:` (a bare `key: value` colon breaks YAML and the description silently fails to load).
2. Split into reference files if SKILL.md would exceed ~100 lines.
3. Add `"./<skill-name>"` to the `skills` array in `.claude-plugin/plugin.json`.
4. Run `./link-skills.ps1` to link it into both local harness directories.
5. Commit + push.
